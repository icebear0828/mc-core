## ⚠️ 已知缺陷、未达标规范与后续整改清单 (Known Limitations & Deficiencies)

经实机初步游玩验证与代码审查，当前 Batch 1 交付存在以下几项严重不符合原版 Minecraft 体验的诟病与缺陷，特此记录在 PR 中以便跟进修复：

---

### 1. 🚨 角色外观未挂载 3D 盔甲外层模型（最严重体验断层）
* **现状缺陷**：
  * 玩家将钻石盔甲（头盔/胸甲/护腿/靴子）装备至对应的 Armor 槽位后，仅在 D3D12 Overlay UI 槽位内显示了图标，并计算了防御点数。
  * **在第三人称游戏视线中，Steve 模型的 12 部位刚体骨骼并没有挂载对应的 3D 盔甲外壳网格（Armor Mesh Overlay）或采样 `diamond_layer_1.png` / `diamond_layer_2.png` 贴图**，外观仍呈现初始裸模状态，视觉与装备完全脱节。
* **整改方案**：
  * 后续批次需在 `steve_rig` / 渲染管线中引入双层盔甲网格附加渲染逻辑，绑定头部、躯干、手臂与腿部关节变换，实现穿戴后实时显示 3D 钻石盔甲。

---

### 2. 🚨 背包 UI 未 100% 还原原版 Minecraft 容器规范
* **现状缺陷**：
  * 当前背包布局直接沿用了之前的 54 格大箱子/调色板网格（`generic_54.png`），并将 4 个盔甲槽和 1 个副手槽临时布局在左侧侧边栏。
  * **原版 Minecraft Java 版生存模式背包（`textures/gui/container/inventory.png`）的标准结构为**：
    1. 左侧：4 个垂直排列的盔甲槽位（Head, Chest, Legs, Feet）；
    2. 中央：玩家 3D 实体动态预览窗口（带鼠标视线追踪偏转）；
    3. 右侧：2×2 简易合成网格与 1 个产物槽（带配方书按钮）；
    4. 下方：3×9（27格）主背包容器 + 底层 9 格快捷栏（Hotbar）；
    5. 右下/左下对应副手槽位（Offhand）。
  * 当前界面的非标准布局破坏了 MC 核心交互记忆与习惯。
* **整改方案**：
  * 提炼原版 `inventory.png` 纹理与 UV 区域，重构 `InventoryLayout` 坐标矩阵，并在中央预留人物 3D 渲染视口与 2×2 合成支持。

---

### 3. 🧪 物理伤害减免实机数值待深层对齐与测试
* **现状说明**：
  * 底层已经在 `PlayerHitSurvival` 接入了 20 护甲点数（80% 物理常态减免）与公式计算，并在单元测试中覆盖了防御减伤断言。
  * 但由于尚未在游戏内完成对抗不同攻击类型（如大树守卫的打击/突刺、失乡骑士的挥砍以及雷电/火焰等非物理伤害）的实战伤害数值校准与完整战斗日志抽样，其实战有效性仍待进一步全面验证。

---

> 📌 **结论**：本 PR 先行合并作为底层装备栏系统、数据协议与基础防御减免的基础设施代码；上述 3 点已登记为最高优先级技术债，将在后续批次专项攻坚补齐。
