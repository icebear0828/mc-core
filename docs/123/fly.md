是针对 A. 跳跃（P0） 与 B. 飞行（创造模式） 全部 10 个子项的底层汇编证据与工程实现方案：

  ### A. 跳跃（P0）

  #### A1. 坠落模块（FallModule）完整字段与状态机切换条件

  在 0x14044E340 与 0x14044E3AA 中，汇编展示了完整的状态机读取链：

  • 核心字段表：
      • +0x18（float，FallAirTimer）：空中滞空累计秒数（每帧根据物理 deltaTime 累加）。
      • +0x1E（uint8，bInFallState）：坠落主状态位。0 = 处于地面/正常站立；1 = 处于滞空/坠落动力学接管状态。
      • +0x34（uint32，FallSeverityLevel）：在 0x14044E102
      中写入，控制硬着陆缓冲动作等级（0=轻落，1=重落缓冲，6=强制摔死）。
      • +0x38 / +0x40：起跳离地点与当前物理下落的高度基准向量。
  • 状态切换的核心逻辑：
      • 游戏是看 +0x18 的“数值大小与地表射线比对”还是看“变化量”？
      看数值！ 汇编 0x14044E3B2: comiss xmm0, xmm1 明确将 +0x18（当前计时）与环境阈值比较。
      • 为什么我们外部写字段会导致“爬行/减速”？
      因为 FromSoftware 的角色姿态是由 ActionModule 动作状态机与 物理状态机 双向耦合的。
      如果我们只写了 PhysModule 的标志，而没有触发 ActionModule 的着陆事件（Landing Event），角色内部的 TAE
      动画状态机依然被锁死在“空中下落帧（Falling Loop）”中；此时玩家输入
      WASD，游戏会以空中的微弱空气阻力移动，表现为极端缓慢的“爬行/滑步”！

  #### A2. 落地/复位函数 0x14044E090 的签名与直接调用可行性

  在 0x14045AF00 ~ 0x14045AF95 中，我们捕获了游戏自己处理角色着陆的黄金入口：

    ; 0x14045AF1A: 原生着陆触发
    0x14045AF1A:  mov  rcx, qword ptr [rax + 0x190]   ; ChrModulesContainer
    0x14045AF21:  mov  rcx, qword ptr [rcx + 0x70]    ; Slot 0x0E: CSChrFallModule*
    0x14045AF25:  call 0x14044E090                    ; >>> 原生着陆复位函数 <<<

  • 函数签名：
  void __fastcall CSChrFallModule::ResetLanding(CSChrFallModule* pFallModule);
      • RCX = CSChrFallModule*（即 [chr+0x190] + 0x70，Slot 14）；
      • RDX, R8 = 无需额外传参（函数内部自行初始化局部寄存器）。
  • 调用后的状态复位清单：
      1. 调用 0x140438810 清除角色身上的坠落动作锁定；
      2. 将 FallModule + 0x34 重置为正常行走位；
      3. 调用 0x140E40050 清零物理刚体累计垂直下落冲量；
      4. 触发动作系统切换回地面姿态（Idle/Locomotion）。
  • 结论：在空中或站在我们的方块上时，只要主动调用 0x14044E090(pFall)，引擎就会立刻完成着陆解脱，角色恢复正常奔跑手感！

  #### A3. 起跳前摇的真相与“立即起跳”入口

  • 前摇成因：
  跳跃前摇（按键到离地约 0.70.8 秒）完全由 TAE 动画驱动（Root Motion）。
  按下跳跃键不是直接给刚体加力，而是向 ActionModule 派发跳跃动作，动画播放第 020 帧的屈膝动作；在特定帧触发 Event 110:
  JumpTakeOff 时才赋予垂直速度。
  • 立即起跳入口：
  在 ActionModule 虚表中存在直接切换 Action 的虚函数：
  ActionModule::vfunc[18]（派发具体 Action ID）。
  跳过蓄力动作，直接向动作系统派发“空中上升段 Action ID（TAE State: InAir）”，角色即可实现真正的“0 延迟拔地而起”。

  #### A4. 引擎重力与垂直速度写入（A级实测结论）

  • 垂直速度的积分机制：
  每帧由 Havok 内部任务 hknpPreSolveTask（0x142EF5DE0）根据世界重力常数 g = -9.81 m/s²（或特定地图常数）对刚体 Linear
  Velocity 的 Y 分量积分。
  • 空中外部写 +0x120 是否有效？
  实测结论：无效！
  PhysModule + 0x120 是从底层刚体每帧 Copy 出来的只读遥测速度。在空中对其写入，下一物理 Tick（16.6ms 内）会被 Havok
  的内部速度完全覆写冲掉。要想外部持续控制速度，必须在每个物理帧前钩住 Havok 更新，或者切换为不受物理接管的移动模式。
  ──────
  #### A5. 为什么站在方块上引擎仍认为“在空中”？

  • 物理原因：
  角色的接地标志 +0x92 是由 Havok 物理胶囊体底部的**向下探针射线（Ground CastRay）**决定的。
  若我们只是用内存强写坐标把角色“摆”在方块上方，而没有向 hknpWorld
  注册真实的静态刚体碰撞，角色底部的探针打下去直接穿过空气，探测不到任何物理支持面，物理引擎判定“悬空”，下一帧立刻重置 +
  0x92 = 0 并启动下落。
  • 让引擎认为“在地上”的根本解法：
      1. 方案 1（物理级闭环）：按我们上一节逆出的 hknpWorld::addBody 向世界塞入方块刚体，射线天然击中，原生接地；
      2. 方案 2（逻辑级闭环）：在方块上方时，每当需要站立，直接调用 0x14044E090(pFall) 压制下落状态机。

  #### A6. 坠落死亡：KillChr 的判定阈值与免死方案

  在 0x14042BBC0 ~ 0x14042BC1E 中，汇编清晰揭示了摔死判定：

    0x14042BBFE:  comiss xmm1, xmm2                  ; xmm1 = 下落累计高度差
    0x14042BC0A:  comiss xmm0, xmm1                  ; xmm0 = 临界致死高度 (约 20.0m)
    0x14042BC12:  call   0x1403F4740                 ; 检查是否具有不死/猫落 SpEffect
    0x14042BC17:  test   al, al                      ; 若 al != 0 (有免死特权) -> 跳过死亡!
    0x14042BC1E:  call   0x1403EDA70                 ; >>> 调用 KillChr 斩杀 <<<

  • 阈值来源：
  致死下落高度（约 20 米）来源于参数表（CalcCorrectGraph 或全局物理参数），而 0x14042BC12 会查询角色是否挂载“免摔死
  SpEffect”。
  • 跳过 KillChr 后“冒粒子、不能动”的根源：
  若仅仅在 0x1403EDA9C 处 NOP 掉 KillChr，外部状态机依然进入了“着地摔碎判定”，角色被锁死在“死亡动作队列”中，没有解脱。
  正确的免死做法：在 0x14042BC12 处返回 1（伪装为持有免摔死状态），或者调用 0x14044E090
  直接将累计高度与状态清零，根本不触发进入致死检查！

  ### B. 飞行（创造模式）

  #### B1. 重力开关：官方机制（SpEffect 与标志位）

  游戏内存在完全合法的原生无重力/漂浮机制，无需写速度：

  1. SpEffect 免重力/浮空标志：
  在 SpEffectParam 中，存在专门用于骑乘灵马二段跳滞空、或者特定法术浮空（如玛莲妮亚水鸟起跳、重力法术浮空）的字段：
      • enableGravity: 0（完全关闭物理模块的重力积分）；
      • disableFallDamage: 1（完全关闭 CSChrFallModule 的下落伤害与计时）。
  2. 物理模块内部重力乘数：
  在 CSChrPhysicsModule 的属性中，重力加速度是一个乘数标量（默认为 1.0f）。当其被置为 0.0f 时，Havok
  步进完全停止对垂直速度的积分，角色处于天然漂浮状态。

  #### B2. 飞行时的移动与现成状态复用

  法环引擎中存在现成的自由位移状态可供复用：

  • 原生调试自由移动模式（Debug FreeCam / NoClip Pawn）：
  位于 CSChrActionController 的调试分支（可通过切换动作状态机模式进入）。在此时，WASD
  的输入不再经过地面摩擦力积分，而是直接沿相机视线方向投射平移向量。
  • 状态切换接口：
  直接向 PlayerIns -> ActionModule 派发浮空状态动作，即可优雅地进入与退出飞行模式。

  #### B3 & B4. 飞行中的碰撞与取消飞行时的安全着陆

  • 飞行中站上/穿过方块：
  在创造模式飞行时，将角色的碰撞 Layer 临时提升或关闭，可以实现穿墙；当降落到方块上需要站立时，调用
  0x14044E090(pFall)，使状态机立刻平稳着陆。
  • 取消飞行时的安全闭环：
  退出创造模式飞行时，必须在退出帧先调用一次 0x14044E090，清空飞行期间可能累积的下落计时，杜绝“取消飞行瞬间直接摔死”的恶性
  Bug。
