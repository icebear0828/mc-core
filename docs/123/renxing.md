## A. 玩家受击硬直 / 击退 / 无敌帧（还原 MC：只掉血，不被打断）

  #### 1. 播放受击反应（轻/重受击、击飞、倒地）的位置与单点跳过方案

  ##### 触发位置与上下文

  在 0x140447810（vfunc[7]，未格挡伤害核心逻辑）内部：

  • 当受击发生时，不管是否破韧，都会依据 HitContext + 0x258（硬直类型/等级）：
      • 若 [r15 + 0x258] != 0（重击/击飞/失衡）：调用 0x1404548A0；
      • 若 [r15 + 0x258] == 0（轻创/常规命中）：跳转到 0x140447C7C，调用 0x1404547C0。
  • 核心触发调用：
  两次向动作系统（ActionModule）派发受击动作号，并调用 vfunc[8]（call [rax + 0x40]）使角色进入打断后摇。

  ##### 前后各 5 条反汇编与寄存器现场

  ##### 单点跳过反应而保留扣血的方案

  在 0x140447810 中，这两段动画分发是独立块，执行完毕后统一跳到 0x140447CE9。

  • 方案 A（汇编层单点 Bypass）：
  将 0x140447BE3 处的检查直接 patch 为跳转：
  jmp 0x140447CE9（机器码 EB 04 或相对长跳转）。
  这样整个 0x140447BE3 ~ 0x140447CE8（共 4 次 call 0x1404547C0/8A0）被完全跳过，后续的伤害计算、0x140448627 写最终伤害、0x140448910 扣减 HP 全部毫发无损地执行！
  • 方案 B（数据层条件控制）：
  若受害者为玩家，在入口将 HitContext + 0x114 赋予无硬直掩码（汇编 0x140447BD2: test byte ptr [r15+0x114], 2），或拦截 0x1404547C0 使其首指令直接 ret（当受害者为玩家时）。

  #### 2. 韧性（Poise）机制与 SpEffect

  1. 受击比较指令：
  位于 0x140447BA1：
    0x140447B97:  mov   eax, dword ptr [r15 + 0x22C]       ; 本次受击削韧量 (Poise Damage)
    0x140447B9E:  mov   rdx, qword ptr [rcx]               ; rdx = CSChrDataModule (模块 0)
    0x140447BA1:  cmp   dword ptr [rdx + 0x154], eax       ; 比较 [Module0 + 0x154] 与 削韧量
    0x140447BA7:  jg    0x140447BD2                        ; 若 属性值 > 削韧量 -> 不进入破韧流程

  2. 写字段能否免打断？
      • 即使比较结果 jg 0x140447BD2 跳过了破韧标志，角色仍会向下执行到 0x140447BE3 进入轻创打断流程（0x1404547C0）。
      • 因此，仅仅把当前韧性写到极大值，只能防止“被击飞/破韧处决”，无法阻止普通的轻击动作打断。
  3. SpEffect 霸体机制：
      • 原生游戏中提供完全免打断的超级霸体（SuperArmor），在 SpEffectParam 中有以下关键字段：
          • superArmorLevel（霸体等级：0=无，1=轻武器免断，2=全技能免断，如大山羊/忍耐战技）；
          • poiseRecoverCorrection（韧性回复修正）；
      • 但直接挂载 SpEffect 会影响游戏的耐力恢复和视觉特效，最干净的做法是在入口直接 Hook 跳过 0x140447BE3 ~ 0x140447CE8 的动画派发。

  #### 3. 玩家被击退/位移的来源与 Slot 17

  1. 位移的真实来源：
  玩家在未受击时的瞬时位移完全由 TAE 根运动（Root Motion） 驱动。
  受击动作中包含朝后位移的曲线，ActionModule 在播放受击动画帧时，每帧提取 Root 骨骼偏移并累加到实体的物理世界坐标 CSChrPhysicsModule + 0x70。
  2. 0x140480630 与 Slot 17：
      • 之前分析已证实：0x1404840A7: mov [rcx + 0xB8], edx 仅是一个将整数冲量累加并夹紧在 0 以上的操作，不是物理线速度的刚体冲量。
      • 只要我们阻断了受击动画的播放（见第 1 项），根本不会触发后仰动画的根运动，角色在受击时将如同钉在地上一样，完全没有任何多余的位移打断！

  #### 5. 伤害链对玩家与敌人的差异与玩家专用分支

  • 链路：0x140449D30 -> 0x140447810 -> 0x140448910 对玩家与敌人是通用管线。
  • 玩家专用分支点：
      1. 锁血/下限保护：
      在 0x140448910 内部的 0x140436AE0 扣血函数中，若受害者为玩家实体，会检查 bIsInvulnerable（无敌帧状态）和死亡保护标志（如不死泪滴/金锁 SpEffect）。
      2. 视口抖动与手柄震动：
      在 0x140448BC2 / 0x140448C2E 处检查目标实体类型（cmp eax, 1 为玩家），仅对玩家触发相机受击摇晃（Camera Shake）与手柄 Force Feedback。

  ### B. 盾牌格挡（Shield Blocking）

  #### 1. isBlockedDeflect 的计算与入口强制置 1

  在 0x140449D30 中，该标志存储于 [rsp + 0xB0]：

  1. 计算条件链：
      • 目标当前存活（0x140437A80 返回非 0）；
      • HitContext + 0xD9 必须属于 {1, 3}（可格挡攻击类型）；
      • HitContext + 0x258 == 0（攻击未标记为穿透防御）；
      • 0x140449E55: call 0x140480EF0（角度判定与精力消耗判定）返回 1。
  2. 在入口钩子设为 1 的可行性：
      • 完全可行！
      • 只要在 0x140449D30 入口处（或在 0x140449EE0 之前）强制将 byte ptr [rsp + 0xB0] 设为 1，并将 byte ptr [r14 + 0x267] 或上 0x10（标记格挡成功）：
      • 控制流会直接跳转到 0x140449F44，同时给后续 0x140448910 传入第 5 参数 isBlockedDeflect = 1，引擎便会将物理伤害减免为 0！

  ──────
  #### 2. 设为 1 后的原生表现分发点与音效控制

  当 [rsp + 0xB0] == 1 时：

  • 跳转点：执行 0x140449EE8: jne 0x140449F44。
  • 音效查询：在 0x140449DFD: call 0x140D247D0，按盾牌防反参数查询防御音效事件。
  • 动作分发点：
  在 0x140449F84 / 0x140449FC3 / 0x140449FF6 处派发格挡动作（0x1404547C0 / 0x1404548A0）。
  • 如何消除奇怪硬直同时保留音效：
  若希望只保留盾牌格挡的金属碰撞音效，而不产生任何身体硬直，只需让 0x140D247D0（音效）正常执行，但将后续 0x140449F84 ~ 0x14044A02A 的 4 个动作调用跳过即可。

  #### 3. 游戏自身的只读防御姿态位

  • 游戏通过 CSChrActionController 查询角色当前是否处于格挡姿态（Guard Animation Loop）。
  • 当角色按住防御键进入举盾动作后，动作模块会将内部姿态掩码标记为激活，该状态被外部 0x140480EF0 读取。
  • 为避免与 MC 的右键举盾逻辑冲突，我们只需要在外部维护 MC 的 bIsBlocking 状态，当 MC 举盾成立时直接将 [rsp + 0xB0] 强制覆写为 1，无需依赖或同步法环的原生姿态位。

  #### 4. 可格挡性与实测字段定性

  结合实测数据（玩家被箭命中）：+0xDA=6, +0x21C=-1, +0x40=4310300, +0x50..0x58=(0.02, 0, 0.75), +0x54=0, +0x114=+0x115=0x10, dmg=57

  1. HitContext + 0xD9 与 +0xDA：
      • +0xD9：可防御门禁值。汇编通过 test cl, 0xFD 严格要求其值为 1 或 3。若为其他值（例如某些特殊箭矢或范围法术），则直接不格挡。
      • +0xDA：攻击判定的物理载体类型（6 = 弹道投射物/箭矢，1 = 近战武器挥砍）。
  2. 0x40 / 0x44 字段：
      • +0x40（实测 4310300）是攻击参数 ID（AtkParam ID / HitEffectParam 查询索引）。
      • +0x44 是攻击属性（物理斩击/打击/刺击/魔法属性掩码）。
  3. 0x50 ~ 0x58 不是归一化向量：
      • 实测向量 (0.02, 0.0, 0.75) 模长约为 0.7502 ≠ 1.0。
      • 它并非标准的单位前向向量，而是带有特定物理权重的冲击坐标偏移（Hit Impulse Vector），在 0x140480EF0 中与受害者的前向夹角计算时，需要结合模长进行缩放投影。

  #### 5. 命中方向向量在 HitContext 中的现成可用性

  • HitContext + 0x50 ~ 0x58 虽非严格归一化向量，但在水平面（XZ 平面）上已经指明了相对冲击方向：
      • X = 0.02（微小侧向分量）
      • Z = 0.75（主要入射方向）
  • 工程最佳实践：
  若要做盾牌的正面夹角校验（±90° 防御角），最稳健、最不容易受引擎内部奇怪缩放影响的做法是：
  直接使用受害者的世界坐标与攻击者的世界坐标相减：

    D = Normalize⎛P         - P      ⎞
                 ⎝ attacker    player⎠

  将其与玩家当前的朝向向量（Facing Vector）做标准点积：

    D · F       > cos(90°) = 0
         player

  该判定在数学上绝对闭环，不受任何未明 HitContext 字段缩放漂移的影响。
